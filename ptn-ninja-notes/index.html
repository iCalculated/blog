PTN Ninja embed notes

From tinue, a rated Tak puzzle trainer. Measured against PTN Ninja v3.8.3 (commit 557628d), November 2026.

Hi gruppler. tinue has an opt-in mode, ?board=ninja, that embeds ptn.ninja in an iframe the way PlayTak does and drives it over postMessage. Building it showed a handful of small changes that would make PTN Ninja a better board for any embedder, PlayTak included.

They're ranked by value per unit of effort. Each one cites the source. Claims marked inferred weren't confirmed in a browser. We're happy to prototype any of them as PRs, in whatever shape you prefer.

What an embedded board costs today

Measured with fresh Chrome profiles on a local page embedding ptn.ninja, and compared with tinue's own board:

Embedded PTN Ninjatinue's board
Before the board appears1.2 MB (≈3 MB of JS)≈0.1 MB
Service-worker precache afterwards6.1 MB, 107 requestsnone
Iframe created → first GAME_STATE, cold0.7–0.8 sn/a
Same, warm (cached)≈0.3 sn/a

The board itself is a small part of this. The rest is the editor, online features and offline cache that load around it. On a cold load the iframe also paints a white page and resizes the board before it settles, so tinue keeps it hidden until it's ready.

Load weight and caching

1 Don't register the service worker inside iframes, and trim the precache effort S

Problem
  • src-pwa/register-service-worker.js:11 registers unconditionally. Only the update popup (line 43) checks Platform.within.iframe.
  • Every first-time visitor to an embed downloads 6.1 MB (measured). Per embedding site, too, since storage is partitioned (inferred).
  • About 4 MB of that is the ten apple-launch-*.png splash screens.
  • The MDI font is cached in both woff and woff2.
  • The -coi revision transform (quasar.conf.js:129–137) also revisions content-hashed files, so they're fetched again instead of reused from the HTTP cache (inferred).
Proposal
  • Wrap register() in if (window.self === window.top).
  • Add workboxOptions.exclude: [/apple-launch-/, /materialdesignicons.*\.woff$/].
  • Apply -coi only to unhashed entries.
The standalone PWA is unchanged.

2 Keep export and online code out of the first-paint bundle effort S–M

Problem
  • JSZip and TPStoPNG are static imports (src/store/ui/actions.js:2, :32) but are used only by the export actions (lines 75, 357).
  • Firebase isn't in the startup import graph, yet it makes up about 656 KB of the 2.1 MB vendor.js. Inferred cause: the default vendor cacheGroup pulls node_modules out of async chunks.
  • markdown-it and its emoji tables load eagerly too.
Proposal
  • Use await import("jszip") and await import(".../TPStoPNG.js") inside the actions that need them.
  • Try build.vendor.remove: ["firebase", "jszip", "markdown-it"].

3 Load only the icons the app uses effort M

Problem
extras: ["mdi-v5"] (quasar.conf.js:20) ships every MDI icon (a 319 KB font plus 272 KB of CSS) for about 150 used.
Proposal
App.vue:59–66 already routes icons through the ICONS map. Map those entries to SVG-path imports from @quasar/extras/mdi-v5 and drop the webfont.

Our rough guess is that 1–3 bring an embed's first load to about 400 KB. The rest is Vue, Quasar and the full editor, so the longer-term win (effort L) would be a board-only embed entry point.

Embed API

4 A READY event effort S

Problem
Nothing tells the host "settings applied, game loaded". GAME_STATE comes from a deep watcher on position (App.vue:256–272). So hosts treat the first one as ready and re-send all their settings, because URL settings don't reliably stick in Firefox (observed; cause unknown).
Proposal
Post {action: "READY", value: {version, ui}} once, after Embed.vue has created the game. It's additive.

5 Tell the player's moves apart from host echoes effort S M for part b

Problem
  • The README says INSERT_PLY is sent "via user interaction". But the onInsertPly hook (store/game/mutations.js:367–369) also fires for host-sent INSERT_PLY.
  • Most host actions are echoed back:
    • SET_UI, once per key (store/ui/mutations.js:29);
    • HIGHLIGHT_SQUARES;
    • GO_TO_PLY, FIRST and LAST;
    • SET_CURRENT_PTN.
  • So a player's rotation looks exactly like a host's SET_UI {boardTransform}.
Proposal
  • (a) Post PLY_PLAYED {ptn, plyID, tps} only from INSERT_PLY_INTERACTIVE (mutations.js:1024).
  • (b) Optionally, let incoming messages carry an id, and stamp what they cause with replyTo.
INSERT_PLY stays as it is.

6 A SELECTION event effort S

Problem
Hosts can't tell when stones are in hand, so they can't stop their own navigation from interrupting a half-made move. The data is already reactive: state.game.selected (mutations.js:451).
Proposal
A watcher next to the GAME_STATE one posts SELECTION {squares, moveset, holding}.

7 Report errors instead of throwing effort S

Problem
  • An unknown action runs throw `Invalid action` (App.vue:214).
  • Bad PTN in INSERT_PLY throws from the Ply constructor (Ply.js:74), and the host never hears about it.
  • Small one: case "GET_THEME" appears twice (App.vue:196, :199).
Proposal
Wrap the switch in try/catch, then post ERROR {action, message} and return.

8 An atomic load effort S

Problem
Loading a game without the fly-in animation takes four messages and a timed wait: SET_UI {animateBoard:false}, then SET_CURRENT_PTN, then LAST, then a sleep, then restoring animation. WITHOUT_BOARD_ANIM (ui/actions.js:300) already does this internally.
Proposal
SET_CURRENT_PTN also accepts {ptn, plyID: "last" | n, animate: false}. A plain string keeps working.

9 Document the outgoing events effort S

Problem
  • The README's API section (README.md:52) covers the commands but lists only 4 outgoing events. The code also posts APPEND_PLY, GAME_END, the echoes, DELETE_PLY, UNDO and more.
  • Useful features that aren't documented:
    • SHOW_NAMES, which hides names and keeps the flat counts;
    • boardTransform and theme as SET_UI keys;
    • engines don't start in an iframe.
Proposal
Document each event's payload and when it fires.

Embed UX and settings

10 Coloured hint highlights effort S–M

Problem
  • HIGHLIGHT_SQUARES tints in the side-to-move's colour at 0.4 opacity (Square.vue:585–591). With a cream player 1 on cream squares, a puzzle hint nearly disappears.
  • The highlighter has per-square colours (Square.vue:147), but it's an editing mode that blocks input.
Proposal
HIGHLIGHT_SQUARES also accepts {squares, color, opacity}, drawn the way the highlighter draws them but without entering highlighter mode.

11 Puzzle guards effort S–M

Problem
  • Playing a different move while a next ply exists creates a branch.
  • disableUndo only hides the buttons (NavControls.vue:93–108). Ctrl+Z is gated on disableNavigation instead (Embed.vue:388–392).
Proposal
  • A noBranches UI key, so such an insert truncates the line.
  • disableUndo also gates the hotkey.

12 Opt-in persistence effort S

Problem
Embed mode skips settings writes (ui/actions.js:129,147) and reads only theme (state.js:211–216), so a viewer's rotation resets on every load. tinue works around this by saving the boardTransform echo itself.
Proposal
A persistUI: ["boardTransform", "themeID"] key that opts the listed keys back into localStorage. Off by default.

Smaller asks

  • Winning road only. At game end the drawn road is the whole winning group after dead-end pruning (Board/end.js:67+). A roadDisplay: "path" option would suit puzzles.
  • Accessibility. From a source read (not audited in a browser), the board has no ARIA labels, keyboard focus or reduced-motion handling. tinue's board has all three if any of it is useful.

What tinue would delete if these landed

#4 removes the "first GAME_STATE means ready" sniffing and the blanket settings re-send. #5 removes the payload shape checks. #6 removes a holding stub that always says "no stones in hand". #8 removes a four-message sequence and a timed sleep. #12 removes our own rotation storage. Our adapter is ninja.js, about 170 lines.

Sources: PTN Ninja at 557628d (github.com/gruppler/PTN-Ninja). Weights were measured with curl and headless Chrome on fresh profiles. tinue is GPL-3 and doesn't include PTN Ninja's code; its board re-implements the input behaviour from its description.
